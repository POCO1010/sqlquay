# 从旧版 Workbench 迁移到 SQLQuay

SQLQuay 的正式 ID 是 `TomMajor.sqlquay`。旧版 `local-workbench.database-workbench` 的配置属于另一个扩展空间；使用本机迁移助手，将连接、凭据和当前工作区绑定送入新空间。

## 先保留恢复入口

保留原来的 `sqlquay-0.4.0.vsix` 或已验证的旧 VSIX。关闭前保留需要的 SQL 与结果；重载会清空会话历史。不要清除或卸载旧版数据，也不要同时启用完整旧版和新版，它们使用相同命令与视图 ID。

## 按顺序迁移

1. 在 VS Code 选择 **Install from VSIX…**，安装 `artifacts/sqlquay-legacy-migration-0.4.3.vsix`，用它替换完整旧版。这个本机助手保留旧扩展 ID，只提供迁移接口，不注册查询命令和视图。
2. 安装正式包 `artifacts/sqlquay-0.5.2.vsix`，然后 **Developer: Reload Window**。
3. 打开原来的工作区。在命令面板执行 **SQLQuay: 从旧版 Workbench 导入连接和当前工作区绑定**，选择要迁移的连接，再核对提示并点 **导入到 SQLQuay**。已有 DMS 时可只勾选 JDBC。
4. 检查连接名称、通道、TLS、工作区默认预览连接，以及已有文件的单独 JDBC/DMS 选择。查询终态未确认的锁也会保留，核实终态后才能解锁。
5. 其他工作区分别打开并执行同一导入命令。连接与密码只在新增对应连接时导入；新版本中已经修改的连接、凭据及显式文件选择不会被旧数据覆盖。

JDBC 用户名和密码只在扩展宿主内存中传递，写入新扩展的 SecretStorage，不写导出文件、日志或剪贴板。导入不会查询数据库，也不会删除源数据。只追加所选且新版没有的连接 ID；不覆盖新版已有连接、凭据、工作区默认值或单文件选择。取消不会读取旧凭据。写入失败会回滚新端修改，并保留旧端。

旧安装未显式配置的策略路径会固定为原来的 `~/.sqlquay/policy/`，继续与已批准的外部 CLI 共用锁；原有显式机器设置保留。新用户设置留空使用附带策略。迁移不切换策略或降低扫描检查。

## 需要恢复旧版时

停用正式 SQLQuay，重新从已保留的旧 VSIX 安装到原扩展 ID，再重载。迁移助手没有改写旧连接、旧凭据或旧工作区绑定；不要先删除扩展存储。待所有常用工作区迁移验收完成后，再决定是否停用迁移助手。

迁移助手只用于本机，不上传 Marketplace。
